# Как создавался «Кампус»

**Проблема.** Расписание, оценки, новости и справки живут в разных местах. Кабинет открывается со сводки на сегодня, а связанные разделы доступны из оглавления.

**Дизайн.** Владелец проекта предоставил сайт онлайн-школы «Спектр» как референс. Из него взяли идею печатного выпуска, оттенки бумаги и чернил, цветовую шкалу и иерархию линеек. Для кабинета сделали отдельный знак и векторную иллюстрацию. Шрифты Playfair Display, IBM Plex Mono и Inter загружаются через Google Fonts, при недоступности используются системные аналоги.

**Использование ИИ.** Codex прочитал требования конкурса и дизайн референса, спроектировал экран, написал HTML, CSS, JavaScript, SVG и Python-сервер. Рабочая постановка — «адаптировать стиль “Спектра” для цифрового деканата и показать работу двух студентов с разными данными». При проверке отдельно сравнивали ответы сервера для разных сессий.

**Данные и вход.** Оба аккаунта вымышленные. База SQLite хранит хеши паролей и сессионных токенов, заявки и отметки о прочтении. Сервер берёт студента из сессии и ищет заявки одновременно по идентификатору заявки и владельцу. Браузер хранит сессионную cookie с HttpOnly и SameSite. Ключ опциональной модели читается из окружения сервера.

**Сценарий демонстрации.** Войти как Алина → открыть ближайшую пару и изменение аудитории → посмотреть баллы и сессию → подать заявку и увидеть «Принята» → спросить помощника о занятиях → выйти и войти как Марк → увидеть другой профиль, расписание и список заявок.

**Границы первой версии.** Поданные заявки получают статус «Принята». Обработка заявок сотрудником, публичное размещение, проверка доступности из России и видео для заявки составляют отдельный этап.

## Итерация по полному заданию конкурса

После повторной сверки с полным заданием добавлены четыре полезных показателя на главной и сводка в разделе «Успеваемость»: невзвешенное среднее, число зачтённых курсов, ближайший контроль и дисциплина с максимальным текущим баллом. Никакой прогнозной аналитики нет: в демо нет истории оценок, весов и проверенной модели. Числовое значение балла остаётся видимым рядом со шкалой.

В расписании добавлена выгрузка выбранного дня или недели в iCalendar `.ics`. Для импорта указана зона `Europe/Moscow`. Добавлены empty state для истории без заявок, семантическая роль журнала беседы и ограничения размера ответа серверной AI-модели. POST-запросы проверяют `Origin` и Fetch Metadata; при HTTPS cookie получает `Secure` и префикс `__Host-`.

### ИИ-инструменты и сервисы

- **OpenAI Codex (настольное приложение)** — разбор задания, прототипирование и доработка Python, HTML, CSS, JavaScript, SVG, README и этой документации; поиск проблем и проверка сценариев.
- **Git и GitHub CLI (`gh`)** — локальный контроль версий и публикация исходного кода в приватном репозитории MGIMO-MIEM-HERO.
- **Python 3 и SQLite** — встроенный HTTP-сервер, локальное хранение данных демо и паролей в виде salted scrypt-хешей. Внешние Python-библиотеки не ставились.
- **Google Fonts** — шрифты Playfair Display, IBM Plex Mono и Inter; при отказе сети остаются системные fallback-шрифты. Рисунок корпуса и знак подготовлены как собственный SVG, генератор картинок не использовался.
- **Поиск в интернете** — проверены первичные рекомендации W3C/WCAG и OWASP, а также обзор исследований аналитических панелей учащихся; ссылки и выводы собраны в `research.md`.

### Ключевые постановки задач

1. «Сначала прочитай подробнее, что и как» — извлечь обязательные сценарии и ограничения из конкурсного задания.
2. «Проанализируй мою работу … изучи статьи … собери всё воедино» — изучить учебный проект и собрать источники, прежде чем предлагать и реализовывать изменения.
3. «…новый репозиторий под ИИ-сайт с кабинетом для студента … возьми оформление» — сделать отдельный работающий прототип в стиле приложенного «Спектра» и разместить исходники в заданной GitHub-организации.
4. «Работай плотно … улучшай, смотри в интернете как лучше сделать» — уточнить продуктовые, accessibility и security-решения, не выдавать демо-аналитику за прогноз и вносить конкретные улучшения.

В этой итерации синтаксическая проверка JavaScript и Python, XML для SVG, `git diff --check` и `docker compose config` прошли. Через браузер проверены вход демо-аккаунта, главная, сводка оценок, расписание, скачивание `.ics` недели с 9 событиями, выход и вход под вторым студентом. На узком окне видимая горизонтальная лента навигации была заменена на сетку; после этого все разделы отображались сразу. Браузерная проверка не является полным аудитом доступности: отдельный проход с экранным диктором и увеличение масштаба до 200% ещё нужны. Docker-образ не собирался; публичный хостинг не создавался и не проверялся из российских сетей. Снимки текущих состояний пока не приложены. Реальных интервью со студентами не проводили — это нужно обозначать именно так, а не заменять вымышленными цитатами.
