# Как создавался «Кампус»

**Проблема.** Расписание, оценки, новости и справки живут в разных местах. Кабинет открывается со сводки на сегодня, а связанные разделы доступны из оглавления.

**Дизайн.** Владелец проекта предоставил сайт онлайн-школы «Спектр» как референс. Из него взяли идею печатного выпуска, оттенки бумаги и чернил, цветовую шкалу и иерархию линеек. Для кабинета сделали отдельный знак и векторную иллюстрацию. Шрифты Playfair Display, IBM Plex Mono и Inter загружаются через Google Fonts, при недоступности используются системные аналоги.

**Использование ИИ.** Codex прочитал требования конкурса и дизайн референса, спроектировал экран, написал HTML, CSS, JavaScript, SVG и Python-сервер. Рабочая постановка — «адаптировать стиль “Спектра” для цифрового деканата и показать работу двух студентов с разными данными». При проверке отдельно сравнивали ответы сервера для разных сессий.

**Данные и вход.** Оба аккаунта вымышленные. База SQLite хранит хеши паролей и сессионных токенов, заявки и отметки о прочтении. Сервер берёт студента из сессии и ищет заявки одновременно по идентификатору заявки и владельцу. Браузер хранит сессионную cookie с HttpOnly и SameSite. Ключ опциональной модели читается из окружения сервера.

**Сценарий демонстрации.** Войти как Алина → открыть ближайшую пару и изменение аудитории → посмотреть баллы и сессию → подать заявку и увидеть «Принята» → спросить помощника о занятиях → выйти и войти как Марк → увидеть другой профиль, расписание и список заявок.

**Границы первой версии.** Поданные заявки получают статус «Принята». Обработка заявок сотрудником, публичное размещение, проверка доступности из России и видео для заявки составляют отдельный этап.
