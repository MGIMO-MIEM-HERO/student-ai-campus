# «Зачёт»: материалы для конкурсной заявки

**Статус:** локально проверенный конкурсный прототип, публичное размещение не завершено.

## Проблема и выбранный сценарий

Кабинет собирает учебные сведения и обращения в одном месте. Главная показывает
не только показатели, но и следующие действия. Путь справки доведён от подачи
до ответа учебного офиса и скачивания явно недействительного учебного образца.
Полезность для реальных студентов пока не измерена; интервью не проводились.

## Состав

Вход и профиль; день и неделя расписания; оценки, зачёты и сессия; заявки;
уведомления; помощник; отдельный демонстрационный учебный офис. Два студента
получают разные данные. Прогнозов успеваемости и интеграции с вузом нет.

## Процесс с ИИ

Исходная история и ключевые постановки сохранены в `process.md`. В доработке
14 ноября 2026 ассистент прочитал официальное задание в авторизованном кабинете,
изучил код и документацию и подготовил изменения по поручению владельца.

Конкретная постановка доработки: закончить путь заявки, сохранить разграничение
данных, связать главную с действиями, проверить телефон 360 px и перезапуск.
ИИ изменил Python, JavaScript и CSS, написал и запустил интеграционные проверки.
При первом прогоне тестов обнаружилась незакрытая SQLite-сессия в тесте;
проверка исправлена через явное закрытие соединения. Это была ошибка теста,
не потеря данных приложения.

Использованы: Codex, Python/SQLite, Node для проверки синтаксиса JavaScript,
Git для локального учёта, браузер для ручного сквозного сценария. Дизайн и
SVG продолжают исходные материалы проекта. Новые изображения генератором
не создавались. Подключение внешней LLM для помощника в этом прогоне не проверялось.
Пользователь самостоятельно выполнил вход в конкурсный кабинет; документы
и согласия участников ассистент не оформлял.

## Вход и защита простыми словами

Сервер проверяет пароль по scrypt-хешу с солью, выдаёт cookie, а в базе хранит
хеш сессионного токена. При чтении заявки проверяются одновременно её номер
и владелец. Студент не может вызвать изменение статуса. Только сотрудник
проходит допустимые переходы. Учебный файл доступен владельцу готовой заявки.
Ключ внешней модели читается только из окружения сервера.

## Проверено 14 ноября

- HTTP: полный путь заявки; чужой номер и документ недоступны; права сотрудника;
  недопустимый переход статуса; сохранение после перезапуска; выход; чужой Origin;
  обновление старой базы; согласованность даты сессии.
- Браузер 360 px: вход Алины, подача заявки, выход, вход сотрудника, два перехода
  статуса, возвращение студентом, ответ и скачивание учебного файла.
- Синтаксис Python и JavaScript. Это не независимый аудит безопасности или WCAG.
