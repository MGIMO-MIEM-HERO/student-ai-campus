# Размещение конкурсного демо

Подготовлен вариант с Caddy, HTTPS и постоянным диском. Он ещё не развёрнут
на публичном сервере; домен, тариф и доступ к хостингу не выбраны.

На сервере с Docker Compose:

1. Направить публичную DNS-запись домена на сервер; обеспечить входящие 80/443.
2. Скопировать `.env.example` в `.env`, указать настоящий домен в `CAMPUS_DOMAIN`.
3. Выполнить `docker compose -f compose.public.yaml config`, затем
   `docker compose -f compose.public.yaml up --build -d`.
4. Проверить HTTPS, оба студенческих аккаунта и сотрудника; перепроверить после
   перезапуска контейнеров, что статусы и заявки сохранены.
5. Открыть домен без VPN из нескольких российских сетей и оставить сервер
   работающим как минимум до 28 ноября 2026 включительно.

Вариант запуска указывает отдельный файл Compose; не объединяйте его с
`compose.yaml`, иначе можно непреднамеренно опубликовать дополнительные порты.
Приложение не публикует 8080 наружу. Сертификаты и SQLite хранятся в volumes.
Команда `down -v` удаляет эти данные — для обычного перезапуска она не нужна.
Резервную копию SQLite делайте штатным backup API при работающем приложении.

Публичное демо использует известные тестовые аккаунты и изменяемые вымышленные
данные. Оно не предназначено для реальных учебных документов. Сотрудник dean
может просматривать все демонстрационные заявки — это намеренная роль,
отдельная от студента. В промышленной системе потребуются иная выдача прав,
защита от злоупотреблений, аудит, мониторинг и масштабирование хранилища.

Источник по автоматическому HTTPS: https://caddyserver.com/docs/automatic-https
Условия DNS и сетевой доступности нужно проверять на выбранном сервере.
