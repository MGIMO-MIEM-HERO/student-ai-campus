# Архитектура Keystone v3

Keystone — концепт личного кабинета университета для трёх ролей: студент, преподаватель и деканат. Название — замковый камень арки: он держит всю конструкцию, как кабинет держит учебный процесс. Все люди и данные вымышлены.

Этот документ описывает то, что реализовано в репозитории. Ранний план перехода на FastAPI, PostgreSQL и React отложен после критики: за отведённое время надёжнее развивать работающий сервер на стандартной библиотеке Python с тестами доступа.

## 1. Принципы

1. **Ответ на главный вопрос роли на первом экране.** Студенту: куда идти и что сдать. Преподавателю: какое занятие, кто пришёл, что проверить. Деканату: какие заявки ждут.
2. **Одно действие — одна кнопка.** Отметить посещаемость, сдать задание, выставить оценку, выдать задание, заказать справку — всё делается из той карточки, где возникла потребность.
3. **Связанные кабинеты.** Действие одной роли сразу видно другой: преподаватель выдал задание — оно у студента в «Заданиях» и в уведомлениях; студент отметил «Сдано» — преподаватель видит сдачу; оценка и комментарий приходят студенту; пропуск в журнале меняет посещаемость в «Учёбе».
4. **Безопасность по умолчанию.** Роль проверяется на каждом запросе. Студент видит только свои данные, преподаватель — только свои группы и дисциплины, деканат — заявки и аудитории.
5. **Спокойный интерфейс.** Белый фон, серые карточки, чёрные действия, один цвет — приглушённое небо в главном блоке страницы.

## 2. Роли и разделы

| Роль | Разделы | Главное действие |
| --- | --- | --- |
| Студент (`alina`, `mark`) | Сегодня, Расписание, Задания, Учёба, Заявки, Корпуса; Уведомления, Новости, Помощник, Профиль | Узнать следующую пару и аудиторию, сдать задание, заказать справку |
| Преподаватель (`vetrova`) | Сегодня, Расписание, Журнал, Задания, Аудитории, Профиль | Отметить посещаемость, проверить работы, выдать задание, написать группе |
| Деканат (`dekanat`) | Заявки, Аудитории, Объявления, Профиль | Провести заявку до выдачи документа, отметить занятую аудиторию |
| Без входа | Проверка документа и студенческого билета по QR | Убедиться, что документ подлинный |

### Студент

- **Сегодня.** Карточка «Сейчас» (текущая или следующая пара, аудитория, преподаватель с фото, задание к паре), шкала дня, четыре числа (пары, задания на 7 дней, средний балл, дни до сессии), ближайшие задания, «что изменилось», карусель преподавателей, новости.
- **Расписание.** Неделя сеткой на компьютере и днями на телефоне; замены «было → стало», окна между парами, задание к паре, экспорт в календарь.
- **Задания.** Группы «Просрочено / Сегодня и завтра / На неделе / Позже», отметка «Сдано» кружком, проверенные работы с баллами и комментарием преподавателя, календарь сроков на две недели.
- **Учёба.** Баллы и допуск по каждой дисциплине, график накопления, посещаемость из журнала, преподаватели семестра, график сессии.
- **Заявки.** Каталог документов со сроками, история заявки как трекинг доставки, электронный документ с QR.
- **Корпуса.** Планы этажей по парам: свободные аудитории, ваше занятие, отметки деканата.

### Преподаватель

- **Сегодня.** Карточка ближайшего занятия с группами, аудиторией и счётчиком присутствующих; кнопка «Отметить посещаемость»; работы, ждущие проверки; зона риска (меньше 60 баллов или посещаемость ниже 75%); карточки групп.
- **Журнал.** Таблица «студенты × занятия» за последние шесть недель: клик по клетке меняет отметку (был → не был → опоздал → уважительная → пусто), итоговые столбцы посещаемости и баллов, строка «присутствовало». Для телефона — лист посещаемости с крупными кнопками и «отметить всех неотмеченных».
- **Задания.** Фильтры «На проверку / Идут / Срок прошёл», прогресс сдачи, лист проверки с баллами и комментарием по каждому студенту, выдача нового задания одной или нескольким группам потока к ближайшему занятию или к дате.
- **Сообщение группе.** Объявление уходит в уведомления студентов выбранной группы.

### Деканат

- **Заявки.** Очередь со статусами, комментарий студенту, выпуск электронного документа с кодом проверки.
- **Аудитории.** Те же планы этажей; отметка «занята» на пару или на день с причиной.
- **Объявления.** Всем студентам или одной группе.

## 3. Поток данных между ролями

```text
Преподаватель ── задание (tasks) ───────────────▶ Студент: «Задания», уведомление «Новое задание»
Студент ──────── «Сдано» (homework_done) ────────▶ Преподаватель: лист проверки, счётчик «Сдали N из M»
Преподаватель ── оценка + комментарий (grades) ──▶ Студент: «Проверено», уведомление «Оценка»
Преподаватель ── отметка (attendance) ───────────▶ Студент: посещаемость в «Учёбе»
Преподаватель ── сообщение (announcements) ──────▶ Студенты группы: уведомления
Деканат ──────── статус заявки, документ ────────▶ Студент: история заявки, документ с QR
Деканат ──────── отметка аудитории (room_marks) ─▶ Все роли: планы этажей
```

## 4. Модель данных

Справочные данные вымышленного кампуса лежат в коде (`campus_data.py`): звонки, корпуса и аудитории, преподаватели, дисциплины групп, сетка расписания, составы групп, демо-задания, новости. Всё, что меняют пользователи, хранится в SQLite.

| Таблица | Что хранит |
| --- | --- |
| `users` | логин, имя, роль, группа; пароль — scrypt с уникальной солью |
| `sessions` | SHA-256 от токена сессии и срок |
| `requests`, `request_events`, `documents` | заявки, история статусов, электронные документы с кодом проверки |
| `cards` | код проверки студенческого билета |
| `announcements`, `notice_reads` | объявления деканата и преподавателей, прочитанные уведомления |
| `room_marks` | отметки деканата о занятости аудиторий |
| `tasks` | задания, выданные преподавателем: группа, дисциплина, срок, занятие, баллы |
| `homework_done` | отметка студента «Сдано» |
| `grades` | баллы и комментарий преподавателя по заданию и студенту |
| `attendance` | отметка посещаемости по занятию и студенту |

Демо-история (прошлые отметки, сдачи одногруппников, старые оценки) строится детерминированно из хеша в `teaching.py`: кабинет выглядит живым в любой день, а изменения пользователей перекрывают её.

## 5. API

Все ответы — JSON; изменяющие запросы — `POST` с проверкой `Origin` и Fetch Metadata.

| Метод и путь | Роль | Назначение |
| --- | --- | --- |
| `POST /api/login`, `POST /api/logout`, `GET /api/session` | все | вход, выход, текущая сессия |
| `GET /api/dashboard` | все | данные кабинета своей роли |
| `POST /api/requests`, `GET /api/requests/<id>` | студент | заявка и её история |
| `POST /api/homework` | студент | отметка «Сдано» |
| `POST /api/notice` | студент | прочитано |
| `POST /api/assistant` | студент | вопрос помощнику |
| `POST /api/teacher/attendance` | преподаватель | отметка одного или нескольких студентов на занятии |
| `POST /api/teacher/tasks`, `POST /api/teacher/tasks/delete` | преподаватель | выдать и удалить своё задание |
| `POST /api/teacher/grade` | преподаватель | баллы и комментарий |
| `POST /api/teacher/announce` | преподаватель | сообщение своей группе |
| `POST /api/staff/requests/<id>`, `/api/staff/rooms`, `/api/staff/announcements` | деканат | статус заявки, аудитория, объявление |
| `GET /api/verify/<code>` | без входа | проверка документа или билета |

## 6. Безопасность

- Роль проверяется на каждом запросе: `/api/teacher/*` только преподавателю, `/api/staff/*` только деканату, студенческие пути только студенту.
- Преподаватель меняет данные только своих пар «дисциплина — группа»: занятие, студент и задание сверяются с его нагрузкой; будущие занятия отметить нельзя; баллы не выше максимума задания.
- Пароли — scrypt с солью; в cookie — случайный токен (`HttpOnly`, `SameSite=Strict`, `__Host-` и `Secure` за HTTPS); в базе — его хеш.
- Ограничение попыток входа: 10 за 5 минут на пару «адрес + логин».
- Строгая CSP без inline-скриптов и стилей; динамические значения передаются через `data-*` и CSS-переменные.
- Ключи внешних сервисов только в переменных окружения сервера; в браузер не попадают.
- Тесты (`tests/test_api.py`): хеши паролей, разделение данных студентов, недоступность чужих заявок, запрет чужих ролей, преподаватель не трогает чужие группы и будущие занятия, сквозные сценарии «задание → сдача → оценка» и «отметка → посещаемость студента».

## 7. Фронтенд

Без сборки: ES-модули в `public/js`, хеш-маршрутизация.

| Файл | Что делает |
| --- | --- |
| `main.js` | оболочка, маршруты по ролям, обработчики событий, формы, обновление данных раз в минуту |
| `student.js` | экраны студента, общие компоненты (заголовок, портрет, пустые состояния) |
| `teacher.js` | экраны преподавателя: сегодня, расписание, журнал, задания, листы посещаемости и проверки |
| `staff.js` | экраны деканата |
| `campus.js` | планы этажей (SVG), стопка этажей в 3D, занятость аудиторий |
| `viz.js` | кольца, графики, шкала дня, недельная сетка |
| `util.js`, `icons.js`, `state.js`, `api.js` | даты по Москве, календарь `.ics`, QR, иконки, состояние, запросы |

Стили: `tokens.css` (цвета, радиусы, тени, шрифт), `app.css` (компоненты), `fonts.css` (Golos Text, SIL OFL).
