# Архитектура «Зачёта» v2

Черновик целевой архитектуры кабинета перед редизайном. Версия 1 (`server.py` на стандартной библиотеке и один `app.js`) доказала сценарии, но не масштабируется и не позволяет быстро менять дизайн. Ниже описано, во что мы её превращаем к 22 ноября и почему.

Статус: 14.11, версия 2. Учтены бенчмарк порталов (`docs/benchmark-portals.md`) и отчёт критика (`docs/critique.md`). Визуальный стиль ждём от владельца.

## 0. Решение после критики

Критик прав: полная замена бэкенда на FastAPI + PostgreSQL + React за 8 дней — главный риск проекта. Поэтому:

- **Бэкенд остаётся** на текущем `server.py` (стандартная библиотека, SQLite, 12 тестов безопасности). Развиваем его по шагам: новые эндпоинты, справка PDF с QR, лента событий. Таблица стека ниже — целевое состояние для масштабирования после конкурса, в отчёте описываем путь миграции.
- **Фронтенд переписываем с нуля** — именно он делает продукт «фиговым»: пять наслоённых тем в CSS, пять семейств шрифтов, меню на полэкрана на телефоне. Новый фронтенд — без сборки (ES-модули + дизайн-токены), чтобы деплой оставался одним контейнером.
- **Публичный HTTPS на российском VPS** поднимаем до редизайна, чтобы жюри гарантированно было что открыть.

## 1. Принципы

1. **Задача за два касания.** Главный экран отвечает на вопросы «что у меня сейчас», «что изменилось» и «что я должен сделать». Остальное доступно через нижние вкладки или поиск.
2. **Одна лента изменений.** Перенос пары, новая оценка, готовая справка и объявление деканата приходят как события одного типа с приоритетом, а не разбросаны по разделам.
3. **Деканат как сервис, а не очередь.** У каждой заявки есть срок, ответственный, история и понятный следующий шаг. Готовая справка проверяется по QR-коду.
4. **Безопасность по умолчанию.** Сервер фильтрует любые данные по владельцу, роль проверяется на каждом запросе, секреты хранятся только в переменных окружения сервера.
5. **Тема — это токены.** Цвета, шрифты, радиусы и плотность задаются CSS-переменными. Новый стиль от владельца подключается заменой одного файла `tokens.css`, без переписывания компонентов.

## 2. Технологический стек

| Слой | Выбор | Почему |
| --- | --- | --- |
| Фронтенд | React 18 + TypeScript + Vite, React Router, TanStack Query | Компонентная модель для редизайна, кеш и состояния загрузки и ошибок «из коробки», типизация защищает от ошибок ИИ-кода |
| Стили | CSS-переменные (дизайн-токены) + CSS Modules, без тяжёлого UI-кита | Тема меняется одним файлом, светлая и тёмная версии, никакой зависимости от чужого визуального языка |
| Иконки | Lucide (ISC) | Открытая лицензия, единый стиль |
| PWA | Web App Manifest + service worker (кеш оболочки и расписания) | Установка на телефон, расписание открывается без сети |
| Бэкенд | Python 3.12 + FastAPI + Pydantic | OpenAPI-схема для жюри, валидация входа, асинхронность. Продолжение текущего Python-кода |
| Данные | SQLAlchemy 2 + Alembic; PostgreSQL в продакшене, SQLite локально и в тестах | Масштабирование до тысяч студентов без смены кода; миграции вместо `CREATE IF NOT EXISTS` |
| Пароли | Argon2id (`argon2-cffi`) | Современный стандарт хеширования (сейчас scrypt; перенос прозрачный при входе) |
| Сессии | Непрозрачный токен в cookie `__Host-` (HttpOnly, Secure, SameSite=Lax), в БД хранится SHA-256 токена | Отзыв сессии, «выйти на всех устройствах», никакого JWT в localStorage |
| ИИ | Серверный прокси к GigaChat / YandexGPT / любому OpenAI-совместимому API; ключ только в окружении | Ключ никогда не попадает в браузер; провайдер меняется переменной |
| Справки | Генерация PDF на сервере (ReportLab) + QR со ссылкой проверки подлинности | Реальный артефакт вместо статуса «Готова» |
| Развёртывание | Docker Compose: `web` (FastAPI + собранный фронтенд), `db` (PostgreSQL), `caddy` (автоматический HTTPS) на российском VPS | Открывается из России без VPN; одна команда для запуска |
| Тесты | pytest (API и права доступа), Playwright (сценарии на 360 px и 1440 px), axe-core (доступность) | Каждое требование жюри покрыто автоматической проверкой |

Альтернатива при нехватке времени: оставить бэкенд на текущем `server.py`, но вынести фронтенд в React. Решение примем после отчёта критика.

## 3. Роли и доступ

| Роль | Видит | Может |
| --- | --- | --- |
| `student` | Только свои профиль, расписание, оценки, заявки, уведомления | Подавать заявки, отменять до начала работы, задавать вопросы помощнику, отмечать прочитанное, настраивать уведомления |
| `staff` (деканат) | Заявки студентов своего факультета, список групп | Менять статус, назначать ответственного, писать комментарий, выпускать справку, публиковать объявления адресно |
| `teacher` (опционально) | Свои занятия и группы | Отмечать перенос или замену пары — событие уходит студентам |
| публичный | Страница проверки справки по QR | Узнать, подлинна ли справка, без персональных данных сверх необходимого |

Правило реализации: каждый запрос к данным идёт через функцию-«политику» (`can_read(user, resource)`), а SQL всегда включает фильтр по владельцу или факультету. Для каждого правила есть тест, который пытается его нарушить.

## 4. Информационная архитектура

Мобильная навигация: нижняя панель из пяти вкладок. На компьютере та же структура в боковой колонке.

1. **Сегодня** (главная, без прокрутки отвечает на «куда идти сейчас — что изменилось — что сделать»): текущая и следующая пара с аудиторией и таймером, блок «Изменилось» (переносы, новые оценки, готовые справки), «Сделать» (дедлайны на 7 дней, заявки, требующие действия), короткий прогресс семестра.
2. **Расписание**: день и неделя, свайп по дням, переносы выделены и объяснены («было — стало»), свободные окна, экспорт в календарь (`.ics` и подписка по ссылке), карточка пары с преподавателем и аудиторией.
3. **Учёба**: дисциплины с баллами, формой контроля и датой; «что нужно для зачёта» (сколько баллов осталось); сессия как таймлайн; долги и пересдачи; рейтинг в группе как опциональный показатель.
4. **Заявки** (деканат): каталог документов (справка об обучении, выписка, справка для военкомата, академический отпуск, перевод, обращение), у каждого — срок, формат (PDF с QR или бумага) и статус-трекер; чат-обращение с деканатом; FAQ с цитатами из положений.
5. **Ещё**: цифровой студбилет с QR, уведомления (лента с фильтрами и «прочитать всё»), профиль, настройки (тема, тихие часы, каналы), помощник, выход.

Глобально: поиск и командная палитра (`/` или кнопка) — «справка», «где 512», «баллы по базам данных». Помощник доступен из любого раздела.

## 5. Модель данных

```text
users(id, login, password_hash, role, faculty_id, created_at, last_login_at)
students(user_id, full_name, program, course, group_id, record_book_no)   -- вымышленные
staff(user_id, full_name, position, faculty_id)
faculties(id, name) · groups(id, name, faculty_id, course)
courses(id, title, assessment, credits)
lessons(id, course_id, group_id, teacher, room, starts_at, ends_at, kind)
lesson_changes(id, lesson_id, kind[move|room|cancel|replace], old_value, new_value, reason, created_at)
grades(id, student_id, course_id, item, points, max_points, created_at)
results(student_id, course_id, status[in_progress|passed|failed|retake], exam_at, final_points)
request_types(id, code, title, sla_days, needs_fields, output[pdf|paper|answer])
requests(id, public_no, student_id, type_id, fields_json, status, assignee_id, due_at, created_at, updated_at)
request_events(id, request_id, status, comment, author_id, created_at)
documents(id, request_id, file_path, sha256, verify_code, issued_at, revoked_at)
announcements(id, author_id, tag, title, body, audience[all|faculty|group], audience_id, pinned, created_at, expires_at)
notifications(id, user_id, kind, ref_id, title, priority, read_at, created_at)  -- единая лента
notification_prefs(user_id, kind, channel, quiet_from, quiet_to)
sessions(token_sha256, user_id, user_agent, expires_at, created_at)
audit_log(id, actor_id, action, target, ip, created_at)                       -- кто что менял
assistant_messages(id, user_id, role, content, created_at)                     -- без отправки ПДн провайдеру
```

Что где хранится:
- **Сервер (PostgreSQL)**: всё перечисленное. Персональные поля только вымышленные. Пароли — только хеши.
- **Файлы справок**: том Docker, имя файла — случайный UUID, отдача только владельцу или по проверочному коду в урезанном виде.
- **Браузер**: только cookie сессии (HttpOnly, JS её не видит) и `localStorage` с настройками интерфейса (тема, последний выбранный день). Никаких оценок и ПДн в локальном хранилище, кроме кеша service worker, который очищается при выходе.
- **Секреты**: `.env` на сервере (ключ ИИ, пароль БД, секрет для подписи QR). В репозитории — только `.env.example`.

## 7. Безопасность

- Контроль доступа на сервере для каждого объекта (защита от подмены ID); публичные номера заявок не последовательные.
- Argon2id, ограничение попыток входа (уже есть: 5 за 15 минут), одинаковое время ответа для существующих и несуществующих логинов.
- Cookie `__Host-`, `HttpOnly`, `Secure`, `SameSite=Lax`; проверка `Origin` и Fetch Metadata для изменяющих запросов (уже есть).
- Строгий CSP без inline-скриптов, HSTS через Caddy, заголовки `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- ИИ-помощник получает только данные текущего студента без ФИО; вопрос считается недоверенным текстом; ответы не меняют данные.
- Журнал аудита действий деканата.
- Тесты: подмена ID, доступ студента к API деканата, межсайтовый POST, отсутствие секретов в бандле фронтенда.

## 8. Тема и дизайн-система

```text
web/src/styles/tokens.css    цвета, типографика, радиусы, тени, отступы, плотность (светлая и тёмная)
web/src/styles/base.css      сброс, фокус, доступность, reduced-motion
web/src/ui/                  Button, Card, Tag/StatusPill, Tabs, BottomNav, Sheet, Toast, Skeleton, EmptyState, ErrorState
```

- Переключатель темы: «Системная / Светлая / Тёмная», выбор хранится в `localStorage`, применяется до отрисовки (без вспышки).
- У каждого экрана три обязательных состояния: скелетон загрузки, пустое состояние с действием, ошибка с повтором.
- Минимальная ширина 360 px, зоны касания от 44 px, контраст WCAG AA, видимый фокус.
- Микроанимации до 200 мс, отключаются при `prefers-reduced-motion`.

## 9. Помощник

Серверный эндпоинт собирает контекст студента (расписание, баллы, дедлайны, статусы заявок) и фрагменты из базы знаний деканата (положения, FAQ — вымышленные или из открытых документов) и отвечает со ссылками «по данным раздела Учёба» или «Положение о справках, п. 3». Без ключа работает справочный режим по правилам (как сейчас). Ответы не меняют данные; действие («заказать справку») помощник предлагает кнопкой, которую нажимает студент.
